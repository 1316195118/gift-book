## 第二轮：P1 + P2 加固（用户「接着做」，Agent 模式）

- **备份链路流式化**：`internal/backup` 新增 `Write(io.Writer, …)`，`Build` 保留为兼容入口；`runAutoBackup` 写临时文件 → fsync → 原子改名；下载改 `http.ServeContent`（支持 Range）；上传导入与列表还原新增 `parseBackupFile`（zip.Reader + ReaderAt），不再把整包读进内存。内存峰值从「整库 zip（可达 512MB）」降为「单条 entry（≤64MB）」。
- **auth 缓存**：`Manager` 对状态与节流表按 mtime+size 缓存，自身写入立即刷新、写失败即失效；`loadState` 读文件出错改为「保持锁定」而非退化成未开启保护；`pruneThrottle` 由 O(n²) 改 `sort.Slice`。
- **导入原子性**：`store.ReplaceAll` 先序列化全部数据并写同目录临时文件，就绪后把旧文件移进 `.trash/` 再统一 rename；切换失败删已切换的新文件并放回旧文件。`writeFileAtomic` 补目录 fsync 与临时文件清理。
- **优雅退出**：`StartAutoBackup` 增加 stop channel + WaitGroup + `sleepOrStop`；`main` 在 Shutdown 后调用 `StopAutoBackup()` 并等待，主 goroutine 也等 shutdown 完成才退出。
- **安全/健壮性**：新增可选 `GIFTBOOK_STRICT_ORIGIN=1`（严格 host:port 同源；**默认兼容模式未变**，现有「同 host 不同端口放行」测试保留）；`decodeJSON` 传 ResponseWriter、拒绝尾部多余 JSON；OCR 临时文件扩展名按检测到的 MIME 固定；前端 `apiRequest` 20s 超时、`authState` 10s 超时并标记 `unknown`（网络失败仍按离线模式继续，避免无密码用户看到登录框）。
- 新增测试：流式 Write、ReplaceAll 前置序列化失败、严格 Origin、缓存感知外部改动、尾部 JSON 拒绝、StopAutoBackup 及时返回、导出 zip 完整性。
- 验证：`go vet ./...`、`go test ./...` 全通过；`npm run build --prefix web` 成功；临时实例跑 `scripts/api-test.mjs` 全通过（含备份导出/恢复）；忽略 CRLF 后所有 Go 文件 gofmt 一致；端到端数据目录无临时文件残留。共 22 文件、+687/-153 行。
